# 随机点名系统 · 程序使用说明

本文面向携带 U 盘到教室上课的使用者，介绍第一次准备、Excel 名单导入和每次上下课的操作。

适用版本：本仓库当前代码构建的 Windows 10 / 11 程序。旧版 EXE 可能没有“点名后立即保存轮次”和“记住数据路径”的修复，请先向程序提供者确认使用的是更新后的 EXE。本文描述的是程序设计行为，具体教室电脑能否从 U 盘运行，需要提前试用确认。

## 一、先确定日常使用方式

**通常直接从 U 盘运行即可，不需要先复制到教室电脑。前提是 EXE 和当前使用的数据 JSON 放在同一个文件夹，且 U 盘可以正常写入。**

| 使用方式 | 上课前要复制到电脑吗？ | 上课时数据保存在哪里？ | 下课后要复制回 U 盘吗？ |
| --- | --- | --- | --- |
| 直接双击 U 盘里的 EXE，使用同目录 JSON | 不需要 | U 盘中的 JSON | 不需要；关闭程序后安全弹出 U 盘即可 |
| 将完整程序文件夹复制到电脑，从电脑运行，并使用电脑上同目录 JSON | 需要复制完整文件夹 | 电脑中的 JSON | **需要**；关闭程序后把最新数据带回 U 盘 |

**数据实际保存在哪里，以程序“设置”中的“数据文件路径”为准。** 只把 EXE 复制到电脑，或启动了桌面上的旧快捷方式，都不能保证正在使用最新的 U 盘数据。程序不会自动同步电脑和 U 盘上的两份 JSON，也不会自动合并两边的记录。

建议日常固定使用第一种方式。只有教室电脑不允许直接从 U 盘运行、U 盘运行不稳定，或学校要求从本机运行时，再按本文第六节操作。

## 二、U 盘里各个文件的作用

建议按下面的方式整理。`随机点名.exe` 与实际数据 JSON 应紧挨着放在同一个文件夹，不要把数据 JSON 单独移入子文件夹。

```text
U 盘/
├── 随机点名/
│   ├── 随机点名.exe
│   ├── rollcall_data.json       ← 首次运行后自动生成
│   ├── rollcall_settings.json   ← 修改过数据位置后才可能出现
│   ├── 程序使用说明.pdf
│   ├── 班级名单/
│   │   ├── 一班名单.xlsx
│   │   └── 二班名单.xlsx
│   └── 导出成绩/
└── 点名备份/
    └── 2026-09-06课后/          ← 举例：关闭程序后备份完整程序文件夹
```

| 文件 | 用途 | 是否随着日常点名更新？ |
| --- | --- | --- |
| EXE 程序 | 打开界面、执行点名 | 否，升级时才替换 |
| 名单 Excel | 初次导入或更新学生名单 | 否，程序不会将评分或轮次写回名单 Excel |
| 数据 JSON，默认名 `rollcall_data.json` | 保存所有班级、名单、历史评分和各班本轮已点名状态 | **是，这是需要保留的主要业务数据** |
| `rollcall_settings.json` | 记住实际使用的数据文件位置 | 修改数据位置时更新；建议随程序文件夹一起携带 |
| 导出的成绩 Excel | 查看、打印、发送成绩统计 | 仅导出时生成，不会自动更新 |

多个班级可以保存在同一个数据 JSON 中。导出成绩 Excel 不能完整恢复点名历史和本轮状态，不能代替 JSON 备份。

**关于 U 盘盘符变化：** 同一个 U 盘在不同电脑上可能显示为 `E:` 或 `F:`。使用默认同目录数据，或通过当前版本设置为 EXE 同目录的数据文件时，程序会随文件夹定位，通常无需调整。将数据放在其他文件夹（包括 EXE 下的子文件夹）或另一块磁盘时，当前程序会记住完整路径，换电脑、换盘符后可能找不到。因此课堂携带场景优先保持 EXE 与数据 JSON 在同一目录。

## 三、第一次初始化：还没有名单和数据

以下只用于真正的首次使用。已经有历史 JSON 的用户请看第四节末尾，不要重新从空名单开始。

1. 在 U 盘中新建“随机点名”文件夹，将更新后的 `随机点名.exe` 放进去。不要直接在 ZIP 压缩包内部双击运行，先完整解压。
2. 插好 U 盘，在文件资源管理器中进入该文件夹，双击 EXE。
3. 程序第一次启动会创建“默认班级”，并在 EXE 旁边生成 `rollcall_data.json`。不需要手动编写 JSON，也不需要安装数据库。
4. 点击工具栏的“重命名”，把“默认班级”改为实际班名，例如“一班”。有其他班级时，点击“新建班级”分别创建。
5. 选择班级，进入“学生管理”，点击“添加学生”，输入学号和姓名。每个班最多 200 人，同班学号不能重复，学号和姓名不能留空。
6. 切换到“随机点名”，核对名单。进入“设置”，确认数据文件位于当前 U 盘的程序文件夹中。仅检查时点击“取消”，避免不必要地切换数据文件。
7. 关闭程序，再从同一个 U 盘文件夹打开一次，确认班级和学生名单还在。至此初始化完成。

建议提前在非上课时间完成初始化。如果要试验点名和评分，可以另建一个“测试班”；正式上课前切回正确班级，避免将测试记录计入正式成绩。

## 四、第一次初始化：已经有 Excel 学生名单

### 1. 整理 Excel

支持 `.xlsx` 文件。旧 `.xls` 文件需先用 Excel 或 WPS 另存为 `.xlsx`。

程序读取工作簿的活动工作表，即保存文件时选中的工作表，读取前两列并跳过第一行。为了减少选错表的情况，建议每个班级一个 Excel 文件、每个文件只保留一张名单工作表。

| A 列：学号 | B 列：姓名 |
| --- | --- |
| 001 | 张三 |
| 002 | 李四 |

准备时注意：

- 第一行直接放“学号、姓名”表头，不要在表头上方再加班级标题或空行。第二行开始放学生。
- 每班 1～200 人。不要在名单末尾添加“合计”“说明”等额外行。
- 每名学生需要学号和姓名，同班学号必须唯一。同名学生请使用不同学号。
- 学号列使用文本格式，尤其是带前导零或很长的学号。若 Excel 已把 `001` 变成 `1`，仅改为文本格式不会自动补回前导零，需要先修正数据。
- 如果工作簿有多张表，先选中要导入的名单表，保存并关闭 Excel，再导入。

### 2. 导入并生成 JSON 数据

1. 按第三节第 1～4 步准备 U 盘程序文件夹、启动程序并创建班级。
2. 在顶部班级选择框中选中要导入的班级，确认班名正确。
3. 进入“学生管理”，点击“导入 Excel 名单”，选择该班的 `.xlsx` 文件。
4. 如果该班已经有学生，程序会询问是否替换名单。确认文件和班级对应后再继续。
5. 导入成功后，核对学生人数、学号、姓名，尤其检查学号前导零。
6. 程序会自动将导入的名单保存到当前数据 JSON，不需要另外点击“生成数据库”。首次启动已经生成的 JSON 会被更新。
7. 其他班级按同样步骤分别导入。所有班级仍保存在同一个 JSON 中。
8. 关闭并重新打开程序，检查各班名单是否恢复。

**导入是替换当前班级的名单，不是追加名单。** 其他班级不受影响，当前班级的历史评分和本轮已点名状态会保留。需要新增一名学生时，可以直接用“添加学生”；需要改学号时，使用“修改选中”，让历史记录和轮次一起更新。不要仅在 Excel 中改成新学号后重新导入来代替程序内的学号修改。

初始化后，日常上课直接读取 JSON。**不需要每次重新导入 Excel。** 修改 U 盘里的 Excel 也不会自动改变程序中的名单，确实需要整体更新时才重新导入。

### 3. 如果已经有旧 JSON 数据

已有 JSON 时，优先接续该数据，其中可能包含 Excel 没有的评分和轮次。

- 有完整旧程序文件夹：退出旧程序并备份文件夹，再用更新后的 EXE 替换旧 EXE，保留原数据和路径设置。
- 只有一份历史 JSON：准备一个新的程序文件夹，将历史 JSON 的副本命名为 `rollcall_data.json`，与 EXE 放在一起后再启动。不要覆盖已有的另一份正式数据。
- 程序已经能正常打开，需要切到另一份历史 JSON：进入“设置”，选择该文件；确认后程序会打开其中的数据，当前数据仍留在原文件。两份数据不会合并。
- v1 旧格式会自动转换，并保留 `.v1.bak.json` 备份。程序不认识或已经损坏的文件会报错，应保留原件交给维护人员检查。

## 五、日常上课：直接从 U 盘运行

### 上课前

1. 插入 U 盘，确认文件资源管理器能正常访问。
2. 从 U 盘的“随机点名”文件夹双击 EXE，不要使用来源不明或上次遗留的桌面快捷方式。
3. 核对顶部班级、学生名单、上次的历史记录，以及右侧“本轮已点名 / 本轮未点名”人数。
4. 第一次在该教室使用，或怀疑数据不对时，进入“设置”核对数据文件路径，确认指向当前 U 盘的程序文件夹。仅查看后点“取消”。
5. 如果这堂课继续上一轮，直接点名即可。若教学安排要求每堂课重新开始一轮，先点击“重置轮询”并确认。**换电脑、重启和跨天都不会自动开始新一轮。**

### 上课中

1. 点击“随机点名”，等待动画结束；或者在名单中选中学生后点击“手动点名”。
2. 点名成功后，该学生的本轮状态立即保存到 JSON。随机和手动方式都不会再次选中本轮已点学生。
3. 需要评分时，调整分数，点击“保存本次记录”。每次结果只能保存一条评分。
4. **先保存本次评分，再继续点名。** 再次点名、切换班级、修改名单、重置轮次或退出后，尚未保存的评分不会自动补存；但已完成的点名仍算本轮已点。
5. 本轮已点人数与累计评分次数可能不同：只点名、没保存评分，会增加本轮已点人数，不增加评分次数。
6. 学生全部点完后，程序询问是否开始新一轮。只有确实需要重复点到所有学生时才确认。
7. U 盘保持连接。出现“点名未保存”“保存失败”等提示时，先处理设备连接、空间或写权限问题，再重试；不要将失败提示当作已保存。

动画期间切换班级会取消尚未完成的抽签，不计入已点名。班级名单的增删改会同步到其他页面。删除学生会保留历史评分和已点状态；删除整个班级会删除该班全部业务数据，操作前先备份。删除最后一个班级后，程序会创建一个空的默认班级。

### 下课后

1. 如最后一名学生需要评分，先点击“保存本次记录”。
2. 在“记录与统计”中检查最后一条评分；如果只点名不评分，则检查本轮已点状态。
3. 如需成绩表，点击“导出本班成绩单”或“导出全部班级”，将文件保存到 U 盘的“导出成绩”文件夹。导出是可选步骤，JSON 数据已随操作保存。
4. 关闭点名程序。也关闭正在使用该 U 盘文件的 Excel、WPS 等窗口。
5. 使用 Windows 的“安全删除硬件 / 弹出”，系统提示可以移除后再拔出 U 盘。若提示仍在使用，先关闭相关窗口，不要直接拔出。

**这种方式没有电脑副本需要回传，JSON 本来就写在 U 盘上，因此不需要再从教室电脑复制 JSON 回 U 盘。**

## 六、需要复制到教室电脑运行时

这种方式会产生 U 盘和电脑两份数据，必须完成课后回传。整个过程只使用一份作为正在编辑的数据。

### 上课前：复制并确认使用本机数据

1. 确认 U 盘里的点名程序已经关闭。
2. 将 U 盘中的完整“随机点名”文件夹复制到教室电脑上学校允许、且可写的位置。**不要只复制 EXE；当前数据 JSON 和路径设置也要一起带上。**
3. 从刚复制到电脑的文件夹双击 EXE，不要启动旧副本。
4. 在“设置”中确认“数据文件路径”指向教室电脑上的这份程序文件夹，并核对班级、记录及轮次。
5. 如果路径仍指向 U 盘或其他位置，这还不是独立的本机运行方式。优先关闭程序，按第五节直接使用 U 盘；需要改为本机方式时，应先按第七节整理成 EXE 与 JSON 同目录，再复制完整文件夹。

对于默认同目录数据，或当前版本已保存为同目录相对文件名的数据，完整复制文件夹后会自动使用电脑副本。但已有旧路径设置、跨文件夹数据等情况仍要实际核对，不能仅凭 EXE 的位置判断。

### 下课后：把最新数据带回 U 盘

1. 保存最后一条需要保留的评分，核对记录及本轮状态，然后关闭电脑上的程序。
2. 确认 U 盘里的程序也没有运行。先把 U 盘现有“随机点名”文件夹备份到 `点名备份/日期-课前版本/`，以保留覆盖前的状态。
3. 将**电脑上本次使用的完整“随机点名”文件夹**复制回 U 盘对应位置，确认来源是电脑课后版本、目标是 U 盘工作版本，再按需覆盖同名文件。
4. 避免仅生成“随机点名 - 副本”却保留旧工作文件夹不动，导致下次仍打开旧数据。确认 U 盘日常使用的那个文件夹已经更新。
5. 从 U 盘日常使用的文件夹再打开程序，核对最后一条评分和本轮已点人数，并检查数据路径现在指向 U 盘。确认后关闭程序。
6. 确认回传成功后，按学校要求清理教室电脑上本次复制的学生数据和程序副本，再安全弹出 U 盘。

**至少必须带回当前实际使用的数据 JSON。** 路径设置若有变化，也要带回 `rollcall_settings.json`；整体复制经核对的同目录程序文件夹更不容易漏文件。名单 Excel 本身不会包含这堂课新产生的记录，只复制 Excel 无法同步课堂数据。

如果两份 JSON 都各自新增了记录，不要简单覆盖来“合并”；先分别保留两份，交由维护人员处理。程序没有自动合并功能。

## 七、数据路径、备份和升级规范

### 将已有自定义数据整理到程序同目录

在程序还能正常打开、原数据路径可以访问时操作：

1. 先核对当前加载的是最新数据。
2. 打开“设置”，选择 EXE 同一文件夹中一个**尚不存在的新 JSON 文件名**，例如 `课堂数据.json`，确认保存。
3. 程序会复制当前全部数据，并记住新位置；原文件保留。
4. 关闭重开，核对班级、最后记录和轮次。以后携带整个文件夹，包括 `课堂数据.json` 和 `rollcall_settings.json`。

选择新文件名是为了避免误读旧文件：**设置里选中已有 JSON 的含义是“打开它”，不是“把当前数据覆盖写进去”。** “恢复默认”也只是选择默认文件位置；如果默认文件已存在，打开的可能是以前留下的旧数据。

如果当前版本因旧绝对路径失效而启动不了，就无法进入设置。先恢复原设备或原文件位置，再按以上步骤整理；无法恢复时，保留现有文件和报错信息，联系维护人员处理。不要反复新建空数据或随意删除路径设置。

### 保持一份明确的工作数据

- 日常使用 U 盘的同一个工作文件夹，备份放到单独的“点名备份”中。不要从备份文件夹开始上课。
- 同一程序目录只允许一个实例运行；不要用两个程序副本同时操作同一份 JSON。
- 不要在程序运行中手动复制覆盖、重命名、移动或编辑当前 JSON。
- 文件名不是数据内容：有多个 JSON 时，以程序设置路径和打开后的班级、记录、轮次确认当前版本。

### 定期备份

- 每次重要课程结束，或导入新名单、删除班级、升级程序之前，关闭程序后按日期备份完整工作文件夹。
- U 盘内的备份方便回退操作，但无法应对 U 盘丢失或损坏。定期在自己的电脑或学校允许的位置保留另一份备份。
- 备份中的 JSON 包含学生姓名、学号和评分，按学校的数据保管要求保存，不留在公共电脑上供他人使用。
- 恢复备份会回到备份时的记录和轮次。恢复前先保留当前版本，不要覆盖掉唯一一份最新数据。

### 升级程序

先关闭程序并备份，之后只替换 EXE，保留当前数据 JSON 和路径设置。重新打开后核对班级、记录和轮次。不要把发布包中的空白数据覆盖到自己的正式数据上。

## 八、遇到问题先检查这些

| 现象 | 优先检查和处理 |
| --- | --- |
| 换教室后看到空名单或旧记录 | 核对启动的是哪一份 EXE，以及设置中的实际 JSON 路径；如果上次在电脑上运行，确认课后已复制回 U 盘。先保留各份数据，不要急着重新导入。 |
| 提示找不到已设置的数据文件 | 检查 U 盘是否连接、盘符或文件夹是否改变；恢复原数据位置后再整理为同目录。启动失败时不能直接在程序内修改设置。 |
| 某学生本轮似乎又被点到 | 确认使用更新后的 EXE、正确班级与最新 JSON；检查是否确认过重置、恢复了较早备份，或同一学生被录入了不同学号。保留数据供维护人员核查。 |
| 点过名但评分次数没增加 | 点名状态与评分分别保存；需要评分时必须点击“保存本次记录”。 |
| 导入失败 | 检查是否 `.xlsx`、活动工作表是否正确、首行是否表头、前两列是否为学号和姓名，以及空值、重复学号和人数限制。 |
| 提示无法写入、点名未保存或评分保存失败 | 保持 U 盘连接，检查剩余空间、写保护和目录权限；处理后重试。 |
| 教室电脑不允许运行 EXE | 按学校允许的方式复制到本机运行，或联系管理人员处理，并遵循第六节的课后回传步骤。 |

## 九、上下课速查

**直接用 U 盘：** 插入 → 从 U 盘启动 → 核对班级 / 数据路径 / 本轮进度 → 点名 → 保存需要的评分 → 课后核对 → 关闭程序 → 安全弹出。**不需要复制回传。**

**复制到电脑用：** 关闭程序后复制完整文件夹到电脑 → 从电脑启动并核对使用本机 JSON → 上课 → 关闭程序 → 备份 U 盘旧版本 → 将电脑课后版本复制回 U 盘 → 从 U 盘打开核对 → 关闭并安全弹出。**必须完成回传。**
