# 随机点名系统

Python / PyQt5 桌面工具，支持班级管理、Excel 名单导入、随机与手动点名、评分、历史查询和成绩单导出。发布目标为 Windows 10 / 11，构建统一使用 Python 3.11。

使用者请先阅读 [程序使用说明（PDF）](docs/程序使用说明.pdf)（[Markdown 源文档](docs/程序使用说明.md)）：包含首次初始化、Excel 名单导入、U 盘直接运行，以及复制到教室电脑运行后的数据回传步骤。

## 开发运行

```sh
python -m venv .venv
# Windows：.venv\Scripts\activate
# macOS：source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
python main.py
```

## 一轮点名的规则

- 随机抽签动画完成、或手动点名成功后，立即将该学号写入本班本轮已点名集合。保存失败时本次点名不生效，并显示错误。
- 评分独立保存。即使没有保存评分就再次抽签、切换班级或退出，已完成的点名也不会在本轮重复。右侧“已点名 / 未点名”展示本轮进度；次数表统计已保存的评分记录。
- 同一抽签结果只能保存一次评分。再次点名会结束上一结果的评分机会，尚未填写的评分不会自动生成。
- 随机和手动点名都排除本轮已点学生。只有确认“重置轮询 / 开始新一轮”才允许重新抽取全部学生，历史评分保留。
- 动画尚未完成时切换班级会取消该次抽签，不计为已点名。已完成的点名状态保留；切班或修改名单会清除待评分选择。
- 重新导入名单保留历史评分及本轮已点学号。删除学生也不清除其历史和本轮状态，重新加入相同学号时仍视为同一人。
- 学号是班级内学生身份，必须唯一；修改学号会同步历史记录和本轮状态，不允许改成已有其他学生历史的学号。同名、不同学号的学生分别统计。学号应使用 Excel 文本单元格以保留前导零。
- 当前版本不提供缺席 / 请假状态；旧设计文档中的相关计划不属于当前功能。

## 数据与恢复

默认数据文件为程序目录下的 `rollcall_data.json`。数据包含班级、学生、评分和各班的 `called_ids`，通过临时文件写入、flush/fsync 后替换原文件。

在“设置”中修改位置：

- 选择不存在的新文件：复制当前数据到该文件，原文件保留。
- 选择已有数据文件：确认后打开其班级、记录和轮次，不覆盖该文件。
- 新路径保存到程序目录的 `rollcall_settings.json`，重启自动恢复。同目录路径使用相对文件名，便于随程序文件夹一起移动。
- 指定的数据文件丢失或外部存储未连接时，程序明确报错并停止，不会悄悄创建空数据或退回旧文件。恢复原文件 / 设备后重启。
- 旧版本已写入自定义文件但重启读回默认文件的情况，可以在设置中重新选择原自定义 JSON。不能仅凭评分历史推断原来的轮次；已被旧版清空的轮次需从备份恢复。
- v1 数据首次加载会保留 `.v1.bak.json` 备份并写入 v2。已点名的对象、学号和姓名格式均转换为学号；姓名有歧义时，将同名学生都视为已点以避免重复抽取。
- 程序目录需要写权限。同一程序目录只允许一个运行实例。不要用不同程序副本同时编辑同一个共享 JSON。

删除最后一个班级后会创建并保存一个空的默认班级，所有页面立即切换到该班级。

## 测试与打包

```sh
python -m pytest -q
```

测试通过临时目录隔离数据，Qt 界面测试使用 offscreen 模式，不改动真实名单。覆盖整轮不重复、未评分时持久化、路径恢复、切班取消、名单同步、学号变更、导入、写入失败和导出等场景。

普通推送和 Pull Request 会运行 Windows 测试；标签发布与手动构建也必须先通过测试，再打包并检查 EXE 启动。详见 [Windows 打包指南](docs/打包指南.md)。

## 代码结构

- `main.py`：应用、主题、单实例锁和启动错误提示。
- `app/ui/`：三个业务页面、对话框及点名动画 / 本轮状态面板。
- `app/logic/`：抽签、统计、学生校验及学号关联更新。
- `app/data/`：模型、版本迁移、数据读写和路径恢复。
- `tests/`：数据、逻辑和界面流程回归测试。

历史设计及实施计划保留在 `docs/superpowers/`，以本说明和现有代码为当前行为依据。
